Demultiplexing & Analysis

After sequencing your pooled, barcoded library, the uSort-M CLI assigns reads to specific wells, performs variant calling, and generates reports for quality control and clone selection.

Overview

The demultiplexing workflow consists of three main steps:

  1. Demultiplexing: Assign sequencing reads to wells based on DNA barcodes
  2. Variant calling: Identify sequences and mutations in each well
  3. Reporting & picking: Generate QC reports and create pick lists for hits

Input Files

Before running the CLI, ensure you have:

1. Sequencing Data (FASTQ)

Raw sequencing reads in FASTQ format from Plasmidsaurus, ONT, or Illumina:

# Example FASTQ file
reads.fastq
# or gzipped
reads.fastq.gz

2. Barcode CSV

Mapping of barcodes to plate positions (see Barcoding for format):

plate,well,barcode
plate_1,A01,ACGTACGTACGT
plate_1,A02,TGCATGCATGCA
plate_1,A03,GCTAGCTAGCTA

3. Reference Sequence (FASTA)

Expected wild-type sequence for variant calling:

>gene_of_interest
ATGGCTAAAGGTGAAGAACTGTTTACCGGTGTTGTGCCGATTCTGGTGGAACTGGATGGT
GATGTGAACGGTCACAAATTCTCTGTGCGTGGTGAAGGTGAAGGTGATGCTACCTACGGT

4. Project Directory (Optional)

If you created a project with usortm plan, the project directory contains metadata:

my_project/
├── project_state.json    # Library parameters
├── plate_layouts/        # Plate maps
└── barcodes.csv         # Barcode assignments

Running Demultiplexing

Basic Usage

# Demultiplex with default settings
usortm demux my_project/ --fastq reads.fastq

If you don't have a project directory, provide files directly:

usortm demux output_dir/ \
  --fastq reads.fastq \
  --barcodes barcodes.csv \
  --reference reference.fasta

Advanced Options

# Custom barcode error tolerance
usortm demux my_project/ \
  --fastq reads.fastq \
  --max-barcode-errors 2

# Filter by minimum quality score
usortm demux my_project/ \
  --fastq reads.fastq \
  --min-quality 10

# Only process specific plates
usortm demux my_project/ \
  --fastq reads.fastq \
  --plates plate_1,plate_2

# Use multiple CPU cores for faster processing
usortm demux my_project/ \
  --fastq reads.fastq \
  --threads 8

Output Files

The demux command generates several output files in your project directory:

1. Well Assignments (assignments.csv)

read_id,plate,well,barcode,num_errors
read_001,plate_1,A01,ACGTACGTACGT,0
read_002,plate_1,A01,ACGTACGTACGT,0
read_003,plate_1,B05,TGCATGCATGCA,1

2. Variant Calls (variants.csv)

plate,well,variant,sequence,quality,num_reads,consensus
plate_1,A01,Y66H,ATGGCTAAAGGTGAAGAACTG...,35.2,45,true
plate_1,A02,F64L,ATGGCTAGAGGTGAAGAACTG...,38.7,52,true
plate_1,A03,WT,ATGGCTAAAGGTGAAGAACTG...,32.1,38,true

3. Quality Metrics (metrics.json)

{
  "total_reads": 125000,
  "assigned_reads": 118500,
  "assignment_rate": 0.948,
  "wells_with_data": 1842,
  "wells_with_consensus": 1756,
  "mean_reads_per_well": 64.3,
  "mean_quality_score": 34.8
}

4. Plate Heatmaps (plate_*.png)

Visual representations of read counts, quality scores, and variant distribution across each plate.

Generating Reports

Create an HTML report with interactive visualizations:

usortm report my_project/

The report includes:

  • Summary statistics (coverage, read depth, quality)
  • Interactive plate heatmaps
  • Variant distribution plots
  • Quality score distributions
  • Per-well read count histograms
  • Barcode assignment statistics

Generating Pick Lists

Create a cherry-picking list for sequence-verified clones:

# Generate pick list for all high-quality variants
usortm pick my_project/

# Filter by minimum quality score
usortm pick my_project/ --min-quality 30

# Select one representative per variant
usortm pick my_project/ --unique-variants

# Export for specific liquid handler
usortm pick my_project/ --format integra

Output format (Integra ASSIST PLUS compatible):

source_plate,source_well,dest_plate,dest_well,variant,quality
plate_1,A01,output_1,A01,Y66H,35.2
plate_1,B03,output_1,A02,F64L,38.7
plate_2,C05,output_1,A03,T203Y,36.1

Quality Control

Expected Metrics

Metric Good Acceptable Poor
Barcode assignment rate >95% 85-95% <85%
Wells with data >70% 50-70% <50%
Mean reads per well >50 20-50 <20
Consensus quality (Q-score) >30 20-30 <20
Variant recovery >90% 75-90% <75%

Troubleshooting

Problem Possible Cause Solution
Low assignment rate (<80%) Barcode errors, wrong barcode file Increase --max-barcode-errors, verify barcode CSV
Few wells with data Low sequencing depth, PCR failures Check sequencing QC, re-run with more cycles
Uneven read distribution Pooling bias, amplification artifacts Normalize inputs before pooling, reduce PCR cycles
Low quality scores Sequencing errors, PCR errors Use higher fidelity polymerase, check read quality
Multiple variants per well Contamination, poor FACS gating Check single-cell mode, use purity gating
Low variant recovery Library skew, insufficient oversampling Increase fold sampling, check transformation scale

Complete Workflow Example

# 1. Plan experiment
usortm plan my_experiment/ \
  --library-size 500 \
  --seq-length 300 \
  --fold-sampling 4 \
  --vector pET28a

# 2. Perform wet lab steps (assembly, sorting, barcoding, sequencing)
# ...

# 3. Demultiplex sequencing data
usortm demux my_experiment/ \
  --fastq sequencing_data.fastq.gz \
  --threads 8

# 4. Generate comprehensive report
usortm report my_experiment/

# 5. Create pick list for high-quality clones
usortm pick my_experiment/ \
  --min-quality 30 \
  --unique-variants \
  --format integra

# 6. Review report and execute cherry-picking
open my_experiment/report.html
